# THAI VOICE SPEC — ระบบบทพูดและคำอ่านภาษาไทย

## 1. ปัญหาที่ระบบต้องแก้

ระบบสร้างข้อความภาษาไทยได้ถูกต้อง แต่เมื่อส่งข้อความเดียวกันให้ระบบ Text-to-Speech หรือโมเดลสร้างวิดีโอ บางคำอาจถูกอ่านผิด จังหวะผิด หรือเน้นเสียงไม่เป็นธรรมชาติ เช่น

- ข้อความที่แสดง: `ลูกค้า`
- คำอ่านที่ใช้สร้างเสียง: `ลูกค๊า`

ดังนั้นระบบต้องแยกข้อมูลเป็น 2 ชั้นอย่างชัดเจน และห้ามใช้ค่าเดียวกันแทนกัน

---

## 2. ฟิลด์บังคับต่อหนึ่งซีน

### 2.1 Display Dialogue

ใช้สำหรับ

- แสดงในหน้าเว็บ
- ซับไตเติล
- Caption
- ข้อความส่งออก Markdown
- ข้อความบนจอ

ข้อกำหนด

- สะกดภาษาไทยให้ถูกต้อง
- เว้นวรรคอ่านง่าย
- ใช้เครื่องหมายวรรคตอนอย่างเหมาะสม
- ห้ามสะกดเลียนเสียงแบบ `ลูกค๊า` ในช่องนี้

### 2.2 Speech Pronunciation

ใช้สำหรับ

- TTS
- Voice Cloning
- AI Video Speech
- Lip-sync

ข้อกำหนด

- อนุญาตให้สะกดเลียนเสียงเพื่อบังคับการออกเสียง
- อนุญาตให้แยกพยางค์
- อนุญาตให้ใส่ช่องว่างเพื่อควบคุมจังหวะ
- ห้ามนำข้อความนี้ไปแสดงต่อผู้ชมโดยอัตโนมัติ

### 2.3 Canonical Word Tokens

เป็นรายการคำมาตรฐานที่ใช้ตรวจจำนวนคำ เช่น

`["เมื่อก่อน", "ห้องไลฟ์", "เงียบมาก", "พอ", "ลองใช้", "พัมไลก์ดอตคอม", "บรรยากาศ", "ดูคึกคักขึ้น", "ฉัน", "มั่นใจ", "ขายสินค้า", "มากขึ้น", "ค่ะ"]`

ระบบต้องเก็บ Token แยกจากข้อความจริงเพื่อไม่ให้การเพิ่มช่องว่างในคำอ่านทำให้จำนวนคำเปลี่ยนผิด

## 3. กฎจำนวนคำ

บทพูดต่อซีนต้องมี 17–20 คำเท่านั้น

### 3.1 วิธีนับ

ไม่ควรใช้การ `split` ด้วยช่องว่างเพียงอย่างเดียว เพราะภาษาไทยไม่มีการเว้นวรรคทุกคำ และคำอ่านอาจถูกแยกพยางค์เพื่อช่วย TTS

ระบบควรมีลำดับการตรวจดังนี้

1. สร้าง Display Dialogue
2. ตัดคำภาษาไทยด้วยตัวตัดคำที่รองรับภาษาไทย
3. รวมคำที่ถูกกำหนดเป็น Phrase เดียวตาม Dictionary
4. บันทึก Canonical Word Tokens
5. ตรวจจำนวน Token ให้อยู่ระหว่าง 17–20
6. สร้าง Speech Pronunciation จาก Token ชุดเดิม
7. หากคำอ่านถูกแยกพยางค์ ห้ามนับเพิ่ม

### 3.2 Phrase Dictionary

คำต่อไปนี้ควรนับเป็นหน่วยเดียวเมื่อใช้ในบริบทเดียวกัน

- ห้องไลฟ์
- ไลฟ์สด
- พัมไลก์ดอตคอม
- เพิ่มการมองเห็น
- ขายสินค้า
- เครื่องสำอาง
- พระเครื่อง
- ทุเรียนหมอนทอง
- โกดังสินค้า
- ลูกค้าออนไลน์

แอดมินต้องเพิ่ม แก้ไข หรือลบ Phrase ได้

### 3.3 สถานะจำนวนคำ

- ต่ำกว่า 17 คำ: แสดงสีเตือนและปุ่ม `เติมคำอย่างเป็นธรรมชาติ`
- 17–20 คำ: ผ่าน
- มากกว่า 20 คำ: แสดงสีเตือนและปุ่ม `ย่อโดยคงความหมาย`

ห้ามส่งไปสร้างเสียงหากยังไม่ผ่าน เว้นแต่ผู้ใช้เปิด `อนุญาตข้ามการตรวจ`

## 4. Pronunciation Dictionary

ต้องมีระบบพจนานุกรมคำอ่านที่แก้ไขได้

โครงสร้างข้อมูล

- Written Form
- Spoken Form
- Category
- Priority
- Apply Globally
- Apply to Project
- Notes
- Active

ตัวอย่าง

| Written Form | Spoken Form | หมายเหตุ |
|---|---|---|
| ลูกค้า | ลูกค๊า | ปรับน้ำเสียงให้เป็นธรรมชาติในบาง Voice |
| ไลฟ์ | ไล้ฟ์ | ลดการอ่านเป็นเสียงอังกฤษแข็ง |
| TikTok | ติ๊ก ต็อก | ใช้เมื่อระบบอ่านภาษาอังกฤษผิด |
| Facebook | เฟซ บุ๊ก | ใช้เมื่อเสียงอ่านติดกัน |
| pumlikes.com | พัม ไล้ก์ ดอท คอม | ชื่อแบรนด์สำหรับเสียงไทย |
| Shopee | ช้อป ปี้ | ใช้ในภาษาไทย |
| Reels | รีลส์ | อ่านแบบไทย |

หมายเหตุ: ตัวอย่างคำอ่านเป็นค่าเริ่มต้นเท่านั้น ผู้ใช้ต้องฟัง Preview และแก้ให้เหมาะกับ Voice Provider แต่ละราย

## 5. ลำดับการสร้างคำอ่าน

ระบบต้องสร้างคำอ่านตามลำดับนี้

1. ใช้ Display Dialogue เป็นฐาน
2. ใช้ Global Pronunciation Dictionary
3. ใช้ Project Dictionary ทับ Global
4. ใช้ Scene Override ทับทุกระดับ
5. ปรับช่องว่างตามจังหวะ
6. ใส่ Pause Markup หาก Provider รองรับ
7. Preview เสียง
8. ให้ผู้ใช้ยืนยันหรือแก้ไข

ห้ามแก้ Display Dialogue เมื่อผู้ใช้แก้ Speech Pronunciation

---

## 6. โหมดแก้ไขเสียง

### 6.1 Normal Mode

แสดงสองช่องคู่กัน

- ข้อความที่ผู้ชมเห็น
- คำอ่านที่ AI ใช้พูด

### 6.2 Word Mapping Mode

แสดงเป็นตาราง

| ลำดับ | คำเขียน | คำอ่าน | ล็อก | ทดลองฟัง |
|---|---|---|---|---|

ผู้ใช้แก้ทีละคำและล็อกคำที่ถูกต้องแล้วได้

### 6.3 Timeline Speech Mode

แสดงช่วงเวลาแต่ละวลี เช่น

- 0.00–1.20 วินาที
- 1.20–2.40 วินาที
- 2.40–4.00 วินาที

รองรับ

- Pause
- Emphasis
- Speed
- Pitch
- Energy

## 7. Voice Preview

ต้องมีปุ่ม

- ฟังทั้งประโยค
- ฟังเฉพาะคำ
- ฟังก่อนแก้
- ฟังหลังแก้
- เปรียบเทียบ A/B
- บันทึกคำอ่านนี้ลง Dictionary

สถานะเสียง

- ยังไม่สร้าง
- กำลังสร้าง
- สร้างสำเร็จ
- ต้องตรวจการออกเสียง
- ผู้ใช้ยืนยันแล้ว
- เกิดข้อผิดพลาด

---

## 8. การควบคุมจังหวะพูด

ผู้ใช้เลือกได้

- ช้าและชัด
- ธรรมชาติ
- กระฉับกระเฉง
- ตื่นเต้น
- อบอุ่น
- จริงใจ
- มั่นใจแบบแม่ค้าไลฟ์

ระบบต้องคำนวณความยาวโดยประมาณจาก

- จำนวน Token
- ความเร็วเสียง
- Pause
- ความยาวของคำ

หากเสียงยาวเกิน Duration ของซีน ระบบต้องเสนอ

- ลดความเร็วภาพ
- เพิ่ม Duration
- ย่อบทพูด
- ลด Pause

---

## 9. ลิปซิงก์

Prompt วิดีโอต้องระบุ

- ผู้หญิงไทยพูดภาษาไทย
- ปากตรงกับเสียงทุกพยางค์
- สีหน้าเป็นธรรมชาติ
- ไม่พูดภาษาอื่น
- ไม่มีเสียงพูดซ้อน
- ไม่มีการขยับปากก่อนเสียง
- ไม่มีการขยับปากหลังเสียงจบ

ระบบควรใช้เสียงที่สร้างเสร็จแล้วเป็นต้นฉบับสำหรับ Lip-sync แทนการให้โมเดลวิดีโอเดาบทพูดจากข้อความ หาก Provider รองรับ

---

## 10. กฎซับไตเติล

ซับไตเติลต้องใช้ Display Dialogue เท่านั้น

- สะกดถูกต้อง
- ไม่ใช้คำอ่านเลียนเสียง
- แบ่งบรรทัดตามความหมาย
- ไม่เกิน 2 บรรทัดต่อช่วง
- ไม่บังใบหน้า สินค้า หรือ UI สำคัญ
- อยู่ใน Safe Area
- ใช้ฟอนต์ไทยที่รองรับวรรณยุกต์

ห้ามใช้ข้อความที่ AI วาดติดมากับภาพเป็นซับไตเติล เพราะมีโอกาสสะกดผิด

---

## 11. ระบบตรวจข้อผิดพลาดภาษาไทย

ก่อน Export ต้องตรวจ

- สระลอย
- วรรณยุกต์ซ้อน
- พิมพ์ตกหล่น
- เว้นวรรคผิด
- คำซ้ำ
- คำอังกฤษอ่านยาก
- ชื่อแบรนด์ไม่ตรง
- Display Dialogue กับ Subtitle ไม่ตรงกัน
- Speech Pronunciation ว่าง
- จำนวนคำไม่ผ่าน

ผู้ใช้ต้องเห็นรายการ Error และ Warning แยกกัน

---

## 12. Prompt สำหรับ AI ที่เขียนบทพูด

AI ต้องปฏิบัติตามกฎ

1. สร้างประโยคภาษาไทยธรรมชาติสำหรับผู้หญิงไทยอายุ 25–27 ปี
2. ใช้ 17–20 Canonical Word Tokens
3. ไม่ใช้คำกล่าวอ้างรับประกันผลลัพธ์
4. ไม่ใช้คำที่ชวนหลบระบบแพลตฟอร์ม
5. สร้าง Display Dialogue ที่สะกดถูกต้อง
6. สร้าง Speech Pronunciation แยกจาก Display Dialogue
7. รักษาความหมายให้เหมือนกันทั้งสองช่อง
8. ใส่คำอ่านแบรนด์ `pumlikes.com` ตาม Dictionary
9. ไม่เพิ่มข้อมูลตัวเลขที่ผู้ใช้ไม่ได้ระบุ
10. คืนผลลัพธ์แบบ Structured Data ไม่ใช่ข้อความก้อนเดียว

---

## 13. ตัวอย่างผลลัพธ์หนึ่งซีน

### Display Dialogue

`เมื่อก่อนห้องไลฟ์ของฉันค่อนข้างเงียบ พอลองใช้ pumlikes.com บรรยากาศดูมีชีวิตขึ้น และฉันก็นำเสนอสินค้าได้มั่นใจมากขึ้นค่ะ`

### Speech Pronunciation

`เมื่อ ก่อน ห้อง ไล้ฟ์ ของ ฉัน ค่อน ข้าง เงียบ พอ ลอง ใช้ พัม ไล้ก์ ดอท คอม บรรยากาศ ดู มี ชีวิต ขึ้น และ ฉัน ก็ นำ เสนอ สิน ค้า ได้ มั่น ใจ มาก ขึ้น ค่ะ`

### หมายเหตุ

- Display Dialogue ใช้แสดงต่อผู้ชม
- Speech Pronunciation ใช้กับ TTS เท่านั้น
- ระบบต้องนับจาก Canonical Tokens ไม่ใช่จำนวนช่องว่างใน Speech Pronunciation

## 15. Acceptance Criteria

- แก้คำอ่านโดยไม่เปลี่ยนข้อความแสดงผลได้
- แก้ข้อความแสดงผลโดยเลือกได้ว่าจะ Sync คำอ่านใหม่หรือไม่
- ตรวจจำนวน 17–20 คำได้สม่ำเสมอ
- แสดงจำนวนคำแบบ Real-time
- Preview ทีละคำและทั้งประโยคได้เมื่อเชื่อม TTS
- Export Subtitle ใช้คำสะกดถูกต้อง
- Export Voice Script ใช้คำอ่าน
- Dictionary มีลำดับ Priority
- คำอ่านของแบรนด์ใช้ซ้ำได้ทุกโปรเจกต์
- ไม่มีคำอ่านเลียนเสียงหลุดไปบนภาพหรือซับไตเติล
